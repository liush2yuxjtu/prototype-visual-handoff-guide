Prototype Delivery · Visual-first

不要解释给我听。
先让我看见，再让我上手。

把 Matt Pocock 的保真度梯子，改造成一套适合 ChatGPT → Human → Coding Agent 的可视化交付路由。

唯一原则：不用固定走完整流程。选择“足以回答当前问题的最低复杂度可视化”。
01 · Fidelity ladder

从“理解”到“真实运行”

这是一把梯子，不是一条必须逐级执行的流水线。答案在哪一层已经足够清楚，就停在哪里。
01 · TEXT
ELI5

解释概念、原因、取舍。高级版文字层。

02 · FLOW
Flow Diagram

顺序、分支、状态怎么变化。

03 · STRUCTURE
Breadboard

有哪些 affordance，它们怎么连接。

04 · SCREEN
Wireframe

东西大概摆在哪里，层级是什么。

05 · FEEL
Runnable Prototype

真正点击以后，体验感觉对不对。

06 · REALITY
Production

真实组件、数据、API、持久化、用户。

低成本 / 抽象 → 高成本 / 真实
02 · ChatGPT-native router

但我们的交付方式不必照着梯子走

点左边一种改动，右边直接显示“最轻、最合适”的交付物。
推荐 · INLINE SVG BEFORE / AFTER

只改一个按钮？不要先动源码。

直接把按钮和它所在的 panel 画成 Before / After，让 Human 一眼判断。流程图、Breadboard、完整 Prototype 都太重。
≈ 30 秒理解成本
03 · The missing middle

流程变化最适合的不是纯 Flowchart，而是 Wireflow

Flowchart 只告诉你“发生什么”；Wireframe 只告诉你“长什么样”。Wireflow 把 Screen + State + Transition 合在一起。
S01 · IDLE
→
S02 · SEARCHING
→
S03 · RESULTS
→
S04 · DETAIL
每一个节点都是一个“用户真的看到的 Screen”，箭头只负责表达 interaction / transition。
04 · Handoff

Prototype 给 Human 决策；Primary Source 给 Agent 接手

不要把 Prototype 再翻译成一份 10,000 字说明。Handoff 应该是一个很小的索引。
